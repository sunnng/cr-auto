# 游戏脚本迁移采用结构直译，不做深度重设计

把帅斌饼干助手（懒人精灵 Lua）的游戏脚本迁移进 cr-auto 时，我们决定按结构直译：保留 Lua 工程 任务/会话/页面/路由/特征库/守卫/调度 的职责分解与文件对应关系，逐模块翻译成 Go 包，直接对接 AutoGo 等价 API；每个 Lua 文件对应一个同名 Go 文件，便于逐文件对照验证。

考虑过的替代方案：auto-cookie 式的深度聚合（Engine/Vision/Brain/Policy 深模块，Lua 只当资料）——其迁移文档明确拒绝 1:1 翻译；"先骨架后按模块决定"的折中方案。两者均被否决：cr-auto 是全新项目无历史包袱，Lua 结构就是事实真值，AutoGo 与懒人精灵 API 一一对应，结构直译成本最低且每个模块可独立对照验收。
